# Android P6 kernel

Android platform code lives under `src-android/ll`, following the client/server platform structure. `main_android.cpp` uses the original ModRegistrar and connects the client lifecycle to Minecraft's Ready and normal-close entries. Android events live under `src-android/ll/api/event`; the corresponding Windows client files are copied there with the same implementation. The Android source table compiles the enabled event copies without compiling `src-client` event sources. The `io`, `memory`, `event` and `mod` modules provide the original LL behavior with only necessary Android backends.

The kernel exports the six API v1 symbols in `scripts/xmake/android-kernel.exports`. A child exports only `LLGetModRegistration` through `LL_REGISTER_MOD` in `ll/api/android/Mod.hpp`; it does not register with PL or Java. Both child context and registration are 56 bytes on AArch64. Context paths remain valid until successful unload. Payloads are borrowed, read-only and valid only during the synchronous callback.

Two provider-owned guarded bindings call the original Actor/ClientInstance function before dispatching their after-event. The ClientInstance return value is preserved. PL owns admission, origin lifetime and the final return barrier. Closing LL does not physically remove those two gateways: successful retirement clears all LL bindings while PL keeps forwarding to the original functions until process exit.

The loader discovers only first-level `type=native` directories, validates manifests/ELF/ABI and creates private immutable generations before first `dlopen`. IDs are ASCII, case-folded for stable ordering and duplicate detection. Entries are single `.so` filenames; arbitrary dependency graphs are outside P6. All listeners are owned by their child and stay inactive until that child's enable succeeds. Callbacks run outside registry locks; external cancellation drains, self-cancellation is permitted, and cross-callback waits are refused.

Shutdown closes publication and drains snapshots/callbacks, disables and unloads children in reverse order, closes their handles, retires ClientInstance then Actor bindings and clears the parent context. Failed child cleanup retains its SO and context and prevents parent unload. A retained failure during child startup is returned to PL after one parent rollback; failed child callbacks are never retried to manufacture recovery.

`Validate-AndroidKernel.ps1` requires all frozen inputs. It builds an explicit source list with NDK r28c, API28, arm64-v8a, C++20, shared libc++, hidden visibility, no exceptions/RTTI, `-z defs` and 16 KiB alignment. Minecraft includes must come from Header S. The Header dependency lane remains API21. `-RunFixtures` runs the separate ABI/lifecycle/guarded adapter/event/native registry fixtures; it requires the matching APK fmt library. `-PackageRoot` creates two deterministic packages only after checking both formal P5 links, their five artifacts, source fingerprints and strip-before/after ELF evidence. Publication switches `current.json` after the whole generation succeeds.

The public-libdl, malformed-loader and performance Mods under `test/android` are fixtures, not package contents. A fixture that manages guarded targets must run separately from LL because the provider permits only one binding per supported call shape. The running Launcher's enabled list is authoritative; editing its configuration file externally does not refresh its in-memory selection.

P6 validation is complete; see [the final acceptance record](android-p6-validation.md). The full shared src/ll compatibility port remains a later phase. Per-process lifecycle transcripts are mirrored into the kernel data directory while the original PL logging route remains active. P5R private CI remains deferred.
